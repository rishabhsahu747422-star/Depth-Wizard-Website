Data

Tile Sampling Strategy

Building and tree pixels are a minority class in a uniform random sample of GAMUS, which compounds the imbalance the training loss already has to correct for. The sampler ranks a candidate pool of 500 tiles by combined building+tree pixel fraction and guarantees at least 150 of the final 350 training tiles are building/tree-heavy, with the remainder filled from the general pool. An 80/20 train/validation split is drawn from this final set.

Data

Ground-Sample-Distance (GSD) Normalisation

GAMUS tiles sit at an implied resolution of roughly 0.33 m/pixel. Feeding the model a wide, district-scale image at a much coarser real-world resolution per pixel causes it to fall back on a natural-image “distant vista” prior and produce structurally meaningless output — confirmed empirically on real Sentinel-2 imagery, not assumed. Every input is center-cropped so that, once resized to the model’s 512×512 input, each pixel represents approximately the training resolution:

crop_side_px = target_gsd_m × model_input_size / source_gsd_m

For GeoTIFF input, source_gsd_m comes from the file’s own geotransform. For PNG/JPG with no embedded metadata, the pipeline explicitly assumes the image already roughly matches training scale rather than guessing a value and presenting it as measured — a documented limitation, not a silent approximation. When the computed crop is smaller than the model’s input size (the source is being upscaled), a mild unsharp mask is applied afterward to recover perceived edge crispness; this compensates for resize blur and does not invent detail absent from the source.

Data

Multi-Tile Handling for Large Images

Images larger than one Stage-1 tile are split into overlapping, GSD-matched tiles rather than being downsampled to fit. compute_tile_grid lays out tile origins with a configurable overlap fraction (default 20%); each tile is run through Stage 1 independently.

Stitching uses a feathered weight mask that tapers toward each tile’s edges (never fully zero, so an edge tile at the image boundary still contributes), and pixels in an overlap region are blended by accumulated weight rather than overwritten. Where an overlap region has enough height variation, a local slope correction is fitted so neighbouring tiles align smoothly instead of showing a seam that tracks the tile grid; a near-constant overlap (most likely to occur at real tile seams) skips this correction since a slope cannot be reliably fit on flat data, and the first tile placed has no prior overlap to align against.

Calibration happens once, after stitching, never per tile. Fitting Stage 2’s affine correction separately on each tile would reintroduce a visible height discontinuity at every tile boundary, defeating the point of feathered stitching. The full image is stitched into one relative height map first, and calibration runs once over the whole result.

Default overlap fraction 20%, default maximum tile count 64 per image.

Model

Backbone Architecture

Depth Anything V2 (Yang et al., 2024), Small variant — a DINOv2 Vision Transformer encoder feeding a DPT (Ranftl et al., 2021) multi-resolution decoder. Only the last N backbone blocks and the full DPT decoder are unfrozen during fine-tuning; earlier blocks, encoding general low-level visual features, stay frozen throughout. N moved from 6 (v1–v3) to 12 (v4, current) across the iteration history below.

Training

Composite Loss Formulation

Three terms, applied per batch over predicted versus ground-truth GAMUS height tiles.

1. Scale-invariant logarithmic loss

The core pointwise term. Working in log-space and subtracting a term proportional to the squared mean log-difference makes the loss invariant to a global multiplicative scale offset between prediction and target — appropriate since Stage 1’s output is relative height by design; absolute scale is Stage 2’s responsibility.

d = log(pred) − log(target)
L_si = mean(d²) − λ·(∑d)²/n²  (λ = 0.5)

2. Multi-scale gradient loss

Penalises mismatches in the log-space spatial gradient (horizontal and vertical finite differences) at the native resolution and three further average-pooled downsamplings (4 scales total). This specifically sharpens edges and boundaries — the scale-invariant term alone can still be satisfied by a blurry prediction.

L_grad = (1/4)∑s=0..3[mean(|∂xp−∂xt|) + mean(|∂yp−∂yt|)]scale s

3. Hard-class penalty

A weighted L1 term restricted to building and tree pixels — the two tall, long-tail-distributed classes heavily outnumbered by trivially-easy near-zero-height ground/road/low-vegetation pixels. Without this term the loss is dominated by the easy majority and building/tree accuracy stalls, a confirmed, diagnosed failure (run v1/v2 below), not a precaution taken speculatively.

L_hard = ∑(|log(pred)−log(target)|·maskbldg∪tree·w) / (∑mask·w)  (w = 3.0)

Combined objective

L = L_si + 0.5·L_grad + 1.0·L_hard

Calibration

Per-Class Affine Fit

Stage 1’s output is a relative height map with no absolute unit. The baseline approach is a single affine fit between relative height and SRTM for the whole scene, by ordinary least squares:

srtm ≈ a · h_rel + b  (one fit, whole scene)

Our approach: an independent (a_k, b_k) per land-cover class k (ground, low-vegetation, building, water, road, tree):

srtm ≈ a_k · h_rel + b_k  (fit independently per class)

Each fit is plain OLS (numpy.linalg.lstsq), not a robust regression. A class with fewer than 30 valid pixels in a tile falls back to the single global fit rather than an unstable per-class estimate from too little data. The coarse SRTM grid is resampled up to Stage 1’s finer prediction grid — not the reverse — so calibration operates at native prediction resolution. Because the backbone is trained on height above local ground rather than global elevation, the final absolute DSM adds back a local ground baseline from SRTM itself:

absolute_DSM ≈ calibrated_relative_height + local_ground_elevation
Calibration

Measured Results

In a synthetic multi-bias test (constructed with a known, different ground-truth bias per class), per-class calibration reduced error by roughly 91% relative to a single global affine fit over the same data — the calibration stage’s own, isolated contribution, distinct from the depth backbone’s own fine-tuning gains reported under Training.

On a real GAMUS test tile run end-to-end through Stages 1→2, most per-class affine slopes came out near-zero (ground a=0.0017, low-vegetation a=−0.0004, building a=−0.0179) — meaning the fit is largely predicting each class’s constant mean height rather than meaningfully using Stage 1’s pixel-level signal. Only tree (a=0.08), road (a=0.12), water (a=0.29), and unlabeled (a=0.18) leaned on real signal.

This is a known limitation of single-tile calibration — narrow within-class height variance on one tile — flagged here rather than presented as a clean result. The calibrated DSM’s overall mean matching the ground-truth mean almost exactly on that run is an artifact of near-zero-slope fitting, not evidence of pixel-level accuracy.
Uncertainty

Why Monte Carlo Dropout Was Rejected

The initial design followed the standard Monte Carlo (MC) Dropout formulation: keep dropout layers active at inference and treat the variance across repeated stochastic passes as an epistemic uncertainty signal. Testing this against the fine-tuned backbone on a real GAMUS tile showed it does not work for this model: its attention_probs_dropout_prob, hidden_dropout_prob, and drop_path_rate are all 0 by default, so repeated stochastic passes are numerically near-identical (variance below 1e-8) and the resulting confidence map collapses to a flat, meaningless constant everywhere. Forcing dropout on at inference was considered and rejected: it would perturb a component the model was never fine-tuned with dropout active in, making the resulting variance unrepresentative of genuine prediction ambiguity rather than an artifact of injected noise.

Uncertainty

Test-Time Augmentation (TTA)

The module was reworked around test-time augmentation: the same input tile is passed through the backbone under N=8 fixed, deterministic perturbations — identity, horizontal flip, vertical flip, both flips combined, and four brightness/gamma shifts — rather than random internal noise. Each output is un-flipped back to the original orientation before aggregation, so all 8 predictions are pixel-aligned:

σ²(x,y) = (1/N)∑i=1..N[h_i(x,y) − μ(x,y)]²

Because the perturbations are external (input-space) rather than internal (weight-space), the variance reflects genuine sensitivity of the depth prediction to viewpoint- and illumination-like changes. On a real held-out GAMUS test tile, this produced a variance range of 0.0004–81.3 (mean 6.2) — a genuinely structured signal, not a flat fallback — with confidence visibly lowest at building and tree-canopy edges, exactly where height discontinuities make the prediction hardest.

Visualization

Per-Instance Roof Plane-Fitting

For each connected blob of a planar land-cover class (buildings by default), a tilted plane is fitted to the blob’s raw predicted heights by least squares, and every pixel in the blob is replaced with the plane’s value:

z = a·x + b·y + c  (least-squares fit per connected blob)

A single plane fitted across a whole gable or hip roof would average both slopes into one incorrect tilted plane instead of a ridge. If the single-plane fit’s residual is too high relative to the blob’s own height range (threshold 0.12 of the range), the blob is re-fit as two planes: PCA on the blob’s pixel coordinates finds its long axis (a gable ridge typically runs along a building’s long axis), the blob is split along the short axis into two halves, and each half gets an independent plane. This is an approximation built entirely from the depth model’s own signal and the land-cover mask; it does not specifically detect hip roofs (4 planes), and falls back to a single plane whenever either half would be too small to fit reliably (under 40 pixels) or the blob itself is too small (under 30 pixels) to fit at all.

Tree canopy is deliberately excluded from flattening — canopy has real internal height variance (branches, gaps) that a plane fit would misrepresent; that is a case for the confidence overlay to flag as uncertain, not for flattening. Flattening runs before the guided filter, and only on buildings — trees are left untouched here because per-tree height is needed by downstream tree-instance detection.

Visualization

Edge-Aware Guided Filter

An edge-preserving guided filter (He, Sun & Tang, ECCV 2010), using the RGB image as guide so smoothing respects real edges instead of blurring across them. For guide I and source (height) map p, over a local window of radius r:

a = cov(I,p) / (var(I) + ε)
b = mean(p) − a·mean(I)
q = mean(a)·I + mean(b)

Default window radius 8 pixels, regularisation ε = 1e-2. Applied after roof plane-fitting, over the full surface including the now-flattened buildings.

Visualization

Rendering & Controls

The processed surface is encoded as a 16-bit grayscale heightmap PNG (65,536 levels, avoiding the visible banding an 8-bit encoding would show on gentle terrain) and decoded client-side to drive per-vertex displacement on a Three.js terrain mesh via react-three-fiber/drei. Three render modes share the same geometry: Elevation (hypsometric per-vertex colour baked into the geometry), Solid (flat-shaded, untextured, relies on per-face lighting to read roof slope), and Imagery (source RGB draped as texture).

Navigation: OrbitControls (@react-three/drei) for orbit/top-down, damped and distance/angle-clamped; a custom WASD + mouse-drag controller for first-person flythrough — not PointerLockControls, since drag-to-look keeps the cursor visible and avoids the browser’s pointer-lock permission prompt.

Implementation

Environment & Dependencies

ML pipeline / backend: Python, PyTorch, Depth Anything V2, rasterio/GDAL, FastAPI. Frontend: React + Vite, react-three-fiber / drei (Three.js). Training: Google Colab, GAMUS streamed via the Hugging Face datasets library. Backend and frontend communicate over local REST calls — no cloud inference dependency.

Known dependency issue. SRTM live fetch uses the elevation package, which shells out to GDAL command-line tools (gdalwarp), not just rasterio’s bundled GDAL — a missing system-level GDAL install causes SRTM fetch to fail even though rasterio itself works for local GeoTIFFs. Diagnosed; not yet confirmed fixed on a fresh run.
Implementation

Pipeline Walkthrough

1. Load image (PNG / JPG / GeoTIFF)
2. If larger than one tile: compute_tile_grid() → overlapping GSD-matched tiles
3. Stage 1: normalize_gsd(image) → crop to training-scale resolution
4. run_inference(cropped) → relative height map
5. run_inference_with_uncertainty(cropped) → height map + 8-pass TTA confidence map
6. If tiled: stitch tiles with feathered blend + overlap slope correction → one relative height map
7. Stage 2 (georeferenced only): fetch_srtm_for_bounds(bounds) → reference DEM
8. resample SRTM up to prediction grid resolution
9. per-class affine fit: relative height → absolute DSM (metres)
10. Stage 3: flatten_planar_classes(dsm, landcover_mask) → per-instance roof plane fit
11. guided_filter(rgb, dsm) → edge-aware smoothing
12. package_result_for_frontend() → 16-bit heightmap PNG + confidence PNG + RGB texture
13. Frontend: decode heightmap → per-vertex mesh displacement → render (Elevation / Solid / Imagery)

Reproducibility

Running It Yourself

The backend and frontend run locally with no cloud dependency: start the FastAPI backend, start the frontend dev server, and call the three endpoints above in sequence. Fine-tuning requires a GPU runtime (Google Colab is what we used) and access to GAMUS via the Hugging Face datasets library. There is no hosted demo — see Home for why.
