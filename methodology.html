Data Engineering

What the model is trained and calibrated against

Dataset composition, sampling strategy, resolution normalisation, and how images larger than one tile are handled.

Fine-tuning uses GAMUS (Xiong et al., 2023): 11,507 paired 512×512 tiles across five US metropolitan areas, each with RGB imagery, a normalised height map, and a land-cover mask across six classes plus unlabelled. Absolute calibration is anchored to SRTM 30 m (Farr et al., 2007), streamed on demand rather than stored in full.

Building and tree pixels are a minority of GAMUS. Left alone, a random sample under-represents exactly the classes that are hardest and most important to get right. Tile sampling instead ranks a pool of 500 candidate tiles by combined building and tree pixel fraction and guarantees at least 150 of the final 350 training tiles are building- or tree-heavy, with an 80/20 train–validation split drawn from that set.

Ground-sample-distance normalisation

GAMUS tiles sit at roughly 0.33 m per pixel. An arbitrary input image at a very different effective resolution reaches the model looking like a different kind of scene — confirmed directly on real Sentinel-2 imagery, which produced structurally meaningless output before this fix. Every input is cropped so that, once resized to the model’s 512×512 input, one pixel represents approximately the training resolution:

GSD normalisation
crop_side_px = target_gsd_m × model_input_size / source_gsd_m

For GeoTIFF input, source_gsd_m is read from the file’s geotransform. For plain PNG or JPG with no coordinates, the pipeline assumes training-scale resolution rather than guessing a number and presenting it as measured.

Large images are tiled, not resized. Above a size threshold the image is split into overlapping tiles (20% overlap, feathered blend weights), run through Stage 1 individually, and stitched into one relative height map before calibration runs once on the full result — fitting calibration per tile would introduce a visible height seam at every tile boundary.
Model & Training

A fine-tuned foundation model, not a network from scratch

What is frozen, what is trained, and how five documented fine-tuning runs led to the current checkpoint.

Stage 1 is Depth Anything V2 (Yang et al., 2024), Small variant — a DINOv2 Vision Transformer encoder feeding a DPT (Ranftl et al., 2021) multi-resolution decoder. It is fine-tuned rather than trained from scratch: general-purpose depth priors from large-scale pretraining transfer partially to nadir geometry, and fine-tuning recovers the rest without needing an unrealistic volume of labelled height data.

Only the last several backbone blocks and the DPT decoder are unfrozen; earlier blocks, which encode general low-level visual features, stay frozen. The number of unfrozen blocks moved from 6 to 12 across the iteration history — see Documentation for the full run-by-run record.

Composite training objective

Three loss terms, each addressing a specific failure seen in earlier runs. Full equations are in Documentation.

Scale-invariant loss

The pointwise term. Invariant to a global multiplicative offset, appropriate since Stage 1 output is relative height by design.
Fixes: nothing, on its own — it is the baseline term.

Multi-scale gradient loss

Penalises mismatched edges at four scales. The scale-invariant term alone can be satisfied by a blurry prediction.
Fixes: the blurry-blob output seen in run v1.

Hard-class penalty

A weighted term over building and tree pixels only, which are outnumbered by trivially easy near-zero ground pixels.
Fixes: building/tree accuracy stalling behind the easy majority.
Scale Calibration

From relative height to metres, per land-cover class

The affine correction and why it is fitted separately per class rather than once for the scene.

Stage 1’s output has no absolute unit. The direct approach is one affine correction fitted between relative height and SRTM for the whole scene, by ordinary least squares. We instead fit an independent correction for each land-cover class, following the finding that semantic context improves height accuracy (Srivastava et al., 2017) and our own observation that classes have systematically different relative-height error.

A class with fewer than 30 valid pixels in a tile falls back to the global fit rather than an unstable per-class estimate from too little data. The coarse SRTM grid is resampled up to Stage 1’s finer prediction grid, not the reverse, so calibration works at native prediction resolution.

An honest result, not a clean one. On a real end-to-end tile, most fitted slopes came out near zero — the calibration mostly predicts each class’s mean height rather than using Stage 1’s pixel-level signal. The full numbers are in Documentation and in Results.
Uncertainty Estimation

Why Monte Carlo Dropout was replaced

A documented failure and the working alternative — full derivation in Documentation.

The first design followed the standard approach, Monte Carlo Dropout: keep dropout active at inference and treat the variance across repeated stochastic passes as uncertainty. It failed outright for this backbone — its dropout probabilities are all zero by default, so repeated passes were numerically near-identical (variance below 1e-8) and the resulting map was a flat, meaningless constant everywhere.

We replaced it with test-time augmentation: eight fixed, deterministic input perturbations (identity, horizontal flip, vertical flip, both combined, and four brightness/gamma shifts), each mapped back to the original orientation before the per-pixel variance is computed. Because the perturbations act on the input rather than the network’s internals, the resulting variance reflects genuine prediction sensitivity.

Visualisation & Mesh Preparation

From a calibrated surface to a navigable terrain

Per-instance roof flattening, edge-aware smoothing, and the render modes available in the 3D viewer.

Before meshing, building footprints are flattened: for each connected blob of a planar class (buildings by default), a tilted plane z = ax + by + c is fitted to the blob’s raw predicted heights by least squares and every pixel in the blob is replaced with the plane’s value. Where a single plane fits poorly relative to the blob’s height range — a sign of a gable or hip roof — the blob is instead split along its long axis (found by PCA) into two halves, each with its own plane. This is the fix for the shape problem that the abandoned v5 structure-loss experiment tried and failed to solve inside the network; imposing it downstream, using the land-cover mask, works. Tree canopy is deliberately excluded — it has real internal height variance a plane fit would misrepresent, better left to the confidence overlay.

An edge-aware guided filter (He et al., 2010) then smooths the full surface, using the RGB image as a guide so smoothing respects real edges instead of blurring across them. Flattening happens first, smoothing second, over everything including the now-flat buildings.

The result is packaged as a 16-bit heightmap — 65,536 levels rather than 256, avoiding visible terracing — alongside the confidence texture and source imagery, and rendered in a Three.js viewer with elevation, solid and imagery modes, orbit controls, and a first-person WASD flythrough.
