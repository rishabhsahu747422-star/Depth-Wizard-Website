Evaluation

What was measured, and what the numbers show

Four evaluation angles: the fine-tuned backbone against zero-shot, calibration against a global fit, uncertainty structure, and out-of-domain generalisation.

Because the backbone is trained with a scale-invariant loss, its raw output is not directly comparable to ground-truth metres — each prediction is aligned to the reference via a per-image scale correction before any error is computed. That alignment is done in linear space (median ratio of prediction to target), not log space: an earlier log-space alignment was distorted by the roughly 34% of pixels sitting near 0 m height (ground/road), so linear alignment is the method used for every number below. Per-class Mean Absolute Error (MAE) is computed on a fixed 30-tile evaluation sample per run, and every reported run is compared against both the zero-shot backbone and the checkpoint it resumed from — a run that beats zero-shot but loses to its own resumed-from baseline is treated as a regression, not progress. That comparison is exactly how v5’s structure-loss experiment was caught.

The most recent independently-verified per-class table. Fine-tuning is ongoing; v4 is the current production checkpoint (12 unfrozen blocks, same loss) but has not yet been re-evaluated on this table — it will be added once reported, not estimated from the v3 trend.

In a synthetic multi-bias test with a known, different bias injected per class, per-class calibration reduced error by roughly 91% relative to a single global affine fit — the calibration stage’s own, isolated contribution, separate from the backbone gains above.

On a real end-to-end test tile, most fitted per-class slopes came out near zero (ground a=0.0017, building a=−0.0179) — meaning the fit is largely predicting each class’s constant mean rather than using Stage 1’s pixel-level signal. Full numbers in Documentation.

On a real held-out GAMUS tile, TTA produced a variance range of 0.0004–81.3 (mean 6.2) — a genuinely structured signal, not the flat fallback MC-Dropout produced — with confidence visibly lowest at building and tree-canopy edges, exactly where height discontinuities make prediction hardest.

Real Sentinel-2 imagery over New Delhi, Kolkata, and the Gangotri Glacier region (hilly terrain GAMUS’s five US cities do not contain) produced structurally plausible output once GSD normalisation was fixed.

This is a qualitative check only. No LiDAR ground truth exists for these scenes, so there is no accuracy number to report — only whether the output structure is plausible.
Ablation

Five iterations, kept in full

Including the run that failed — the reason it failed is itself a finding, not something to hide.

  1. v1 — 2 unfrozen blocks

    Scale-invariant loss only. Buildings and trees came out as blurry, low-detail blobs — the first sign that a plain pointwise loss is not enough.

  2. v2 — 6 unfrozen blocks

    Added gradient and class-weighted loss. Bug: the class-weighting code targeted the wrong class ID (road instead of tree). The apparent improvement in this run was illusory.

  3. v3 — 6 unfrozen blocks

    Corrected class IDs; building and tree weighted together as intended. Confirmed real: overall MAE fell 6.996 m → 4.223 m (−40%) against zero-shot.

  4. v4 — 12 unfrozen blocks (current)

    Same three-term loss, wider unfreeze. This is the production checkpoint today. Its own per-class table has not yet been re-reported — see the callout below.

  5. v5 — 12 unfrozen blocks

    Added a fourth “structure loss” term meant to encourage flat roofs. Abandoned: it regressed MAE across every land-cover class. The shape problem it was trying to solve was fixed instead as post-processing (see Documentation).

v4 status. Confirmed as the current production checkpoint by inspection of the shipped pipeline. Its full per-class MAE table is pending re-report; the v3 table above remains the last independently-verified numbers on record.
Known Issues

What is not resolved yet

Generalisation testing is qualitative only. No ground truth exists for the real-world Sentinel-2 test scenes.
Raw output has pixel-level noise that looks poor fed directly into a mesh; the guided filter helps but cannot invent detail Stage 1 never predicted. A true fix means retraining with more unfrozen blocks and an edge-aware loss term.
SRTM live fetch was failing due to a missing system-level GDAL CLI dependency — diagnosed and documented, not yet confirmed fixed on a fresh run.
The frontend confidence-layer toggle was reported not working as of the last check; not yet re-verified.
