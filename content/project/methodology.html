1. Depth Anything V2 Backbone & Freezing Strategy

Depth Anything V2 (Yang et al., 2024) uses a DINOv2 Vision Transformer encoder feeding a DPT (Ranftl et al., 2021) multi-resolution decoder. We use the Small variant, initialized from its pretrained weights and fine-tuned rather than trained from scratch, for the transfer-learning reasoning laid out in Proposed Solution.

Only the last N backbone blocks and the DPT decoder head/neck are unfrozen during fine-tuning — the earlier blocks, which encode general-purpose low-level visual features, are kept frozen. N is not fixed a priori: it moved from 6 (v3) to 12 (v4, current) across the iteration history below, since more unfrozen capacity gave the model more room to adapt to nadir geometry without yet showing overfitting on this dataset size.

2. Ground-Sample-Distance (GSD) Normalization

GAMUS tiles are neighborhood-scale, at an implied resolution of roughly 0.33 m/pixel (a comparison-table figure from Xiong et al., 2023's follow-on literature, not stated directly in the GAMUS paper itself — treated as a well-sourced estimate, not an authoritative constant). Feeding the model a wide, district-scale image at a much coarser real-world resolution per pixel causes it to fall back on a natural-image "distant vista" prior and produce structurally meaningless output — this was confirmed empirically on real Sentinel-2 imagery before the fix, not assumed. Every input is therefore center-cropped so that, once resized to the model's 512×512 input, each pixel represents approximately the training resolution:

crop_side_px = target_gsd_m × model_input_size / source_gsd_m

For GeoTIFF input, source_gsd_m comes from the file's own geotransform. For PNG/JPG with no embedded metadata, the pipeline explicitly assumes the image already roughly matches training scale rather than guessing a value and presenting it as measured — a documented limitation, not a silent approximation. When the computed crop is smaller than the model's input size (i.e. the source is being upscaled), a mild unsharp mask is applied afterward to recover perceived edge crispness — this does not invent detail that was not in the source, it only compensates for resize blur.

3. Composite Loss Formulation

The backbone is fine-tuned against a three-term objective, applied per-batch over predicted vs. ground-truth GAMUS height tiles:

3.1 Scale-Invariant Logarithmic Loss

The core pointwise regression term. Working in log-space and subtracting a term proportional to the squared mean log-difference makes the loss invariant to a global multiplicative scale offset between prediction and target — appropriate here because Stage 1's output is relative height by design; absolute scale is Stage 2's responsibility, not this model's.

d = log(pred) − log(target)
L_si = mean(d²) − λ · (∑d)² / n²   (λ = 0.5)

3.2 Multi-Scale Gradient Loss

Penalizes mismatches in the log-space spatial gradient (horizontal and vertical finite differences) between prediction and target, computed at the native resolution and at three further average-pooled downsamplings (4 scales total). This is what specifically sharpens edges and boundaries — the scale-invariant term alone optimizes pointwise accuracy and can still be satisfied by a blurry prediction.

L_grad = (1/4) ∑s=0..3 [ mean(|∂xp − ∂xt|) + mean(|∂yp − ∂yt|) ]scale s

3.3 Hard-Class Penalty

An additional weighted L1 term restricted to building and tree pixels — the two tall, long-tail-distributed classes that are heavily outnumbered by trivially-easy near-zero-height ground/road/low-vegetation pixels. Without this term, the loss is dominated by the easy majority and building/tree accuracy stalls; this was a confirmed, diagnosed failure mode in an early iteration (see history below), not a precaution taken speculatively.

L_hard = ∑( |log(pred) − log(target)| · mask_{building∪tree} · w ) / (∑mask · w)   (w = 3.0)

3.4 Combined Objective

L = L_si + 0.5 · L_grad + 1.0 · L_hard

Optimized with AdamW, learning rate 1e-4, batch size 4, up to 30 epochs with early stopping (patience 5 epochs without validation-loss improvement).

4. Fine-Tuning Iteration History

Five documented iterations, kept here in full rather than presenting only the final result — including the one that failed, because the reason it failed is itself a methodological finding:

Run Unfrozen blocks Change Outcome
v12 Scale-invariant loss only Buildings/trees came out as blurry blobs
v26 Added gradient + class-weighted loss Bug: weighted the wrong class ID (road, not tree) — apparent improvement was illusory
v36 Corrected class IDs; weight building & tree together Confirmed real: overall MAE 6.996m→4.223m (−40%) vs. zero-shot
v4 (current)12 Same 3-term loss, wider unfreeze Production checkpoint. Full per-class table pending re-report (see note below)
v512 Added a 4th "structure loss" term (roof flatness) Abandoned: regressed MAE across every land-cover class

v5's failure is treated as a real result, not discarded: it shows the depth backbone is the wrong place to enforce roof/building shape. That concern was resolved instead in Stage 3 post-processing (land-cover-guided plane fitting), which fixes shape without touching the depth model's numeric accuracy — see 3D Terrain Flythrough.

Status: v4 is the current production checkpoint (confirmed via code inspection of the shipped pipeline). The v3 numbers above are the last independently-verified per-class MAE table we have on record. Fine-tuning is ongoing; v4's own per-class table will be added here once a run is reported and confirmed, rather than estimated from v3's trend.

5. Scale Calibration (Stage 2)

Stage 1's output is a relative height map with no absolute unit. Recovering an absolute DSM requires anchoring it to a real elevation reference — here, SRTM 30 m (Farr et al., 2007). The baseline approach is a single global affine fit between the two, by ordinary least squares:

srtm ≈ a · relative_height + b   (least-squares fit over all valid pixels)

Our contribution: instead of one global (a, b) for an entire scene, we fit a separate (a, b) per land-cover class (ground / low-vegetation / building / water / road / tree), using the same semantic masks the depth backbone was trained alongside. This follows directly from Srivastava et al. (2017)'s finding that semantic context improves height accuracy, and from our own Stage 1 evaluation showing building and tree classes have systematically different relative-height error characteristics than flat ground/road. A class with fewer than 30 valid pixels in a given tile falls back to the global fit rather than producing an unstable per-class estimate from too little data. In a synthetic multi-bias test, per-class calibration reduced error by roughly 91% versus the global fit.

Because the backbone was trained on nDSM-style relative height (height above local ground, not global elevation), the final absolute DSM adds back a local ground baseline from SRTM itself: absolute_DSM ≈ calibrated_relative_height + local_ground_elevation.

6. Uncertainty Estimation

Covered in full, including the rejected Monte Carlo Dropout attempt and why it failed, in Uncertainty Mapping. In summary: 8 fixed test-time-augmentation passes (flips + brightness/gamma perturbations) rather than stochastic internal noise, since the backbone's dropout is 0 by default and produces no usable signal.
